# ver0.1.8 利用状況計測定義

状態: 実装済み / 本番送信先は接続済み / 公開日は未定

本番送信先: `https://alwaysmemo-analytics.ugomemo.workers.dev/v1/events`

送信はアプリ内の「改善に協力する」を選んだ後だけ開始する。「あとで」
では送信もランダムID作成も行わない。設定から停止でき、停止時はランダムID、
セッション、未送信キューを削除する。

「あとで」の初回選択後は、7日以上かつ3日以上の異なる利用日を満たした場合に
再案内する。2回目の選択後は30日後に最終案内し、3回目以降は自動表示しない。
延期回数、延期日時、最大3日分の利用日は端末内だけに保存し、外部送信しない。
旧版ですでに「あとで」を選んだ利用者は、更新日から最初の待機期間を開始する。

送信項目はイベント定義v1、イベントID、発生時刻、ランダムなインストールID、
共有セッションID、アプリ版、UI言語、実行環境、許可されたイベント属性のみ。
メモ本文、ファイル名・パス、ウィンドウタイトル、クリップボード、氏名・メール、
ハードウェア識別子、生の例外メッセージは送信しない。

イベントは、参加開始、セッション開始、最初の実編集、中核操作成功、
オンボーディングの表示・手順・完了・スキップ、既定アプリ・レビュー案内、
ファイル読込・保存の成功・キャンセル・失敗を対象とする。復元は実編集・
中核操作に数えず、IME変換中は編集確定としない。既定アプリ設定画面を
開いたことは設定成功とは扱わない。

ローカルキューは最大500件か512KiB、最長30日、1回20件、5秒でタイムアウト。
再試行は1分、5分、30分、2時間、8時間の最大5回。通常の編集・保存を待たせず、
受信側はイベントIDで重複排除する。D1の生データは90日で削除する。
受信側は検証済みのインストールID単位で毎分60リクエストに制限し、
制限超過時はD1へ書き込まずHTTP 429を返す。

公開プライバシーポリシーには、上記の収集目的、Cloudflareへの送信、
ランダムID、90日保持、停止方法を反映済み。

## 開発モードで初回案内を再検証する

開発モードは`ver0.1.8`の開発ビルドに限定され、本番ビルドには入口を表示しない。
本番Workerではなく、`127.0.0.1:8787`のローカルWorkerとローカルD1を使用し、
送信イベントの`environment`は`test`に固定する。

1. PowerShellを2つ開く。
2. 1つ目で`cd C:\projects\alwaysmemo\analytics-worker`を実行する。
3. 初回だけ`npx wrangler d1 migrations apply alwaysmemo-analytics --local`を実行する。
4. `npx wrangler dev --local --var ALLOWED_ORIGINS:http://localhost:1420`を実行する。
5. 2つ目で`cd C:\projects\alwaysmemo`を実行する。
6. `npm run tauri dev`を実行する。この操作で自動的に開発モードになる。
7. AlwaysMemoの歯車ボタンから設定を開く。
8. プライバシーの下にある「開発モード」までスクロールする。
9. 対象のリセットボタンを押し、確認画面で許可する。
10. 設定画面が閉じ、メイン画面が再読み込みされた後の案内を検証する。

「同意案内を再表示」は同意、再案内履歴、仮名ID、セッション、未送信キュー、導入判定を削除する。
「オンボーディングを再表示」は完了状態だけを削除する。「初回案内をすべてリセット」は
これらに加えて既定アプリ、レビュー、ヘルプ案内の表示履歴を削除する。レビュー案内は
利用日数などの通常条件を満たした時点で表示され、リセット直後には強制表示しない。
いずれもメモ本文、タブ、ファイル情報、テーマなどの通常設定は削除しない。
